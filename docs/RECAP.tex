\section{Project Overview}
%----------------------------------------------------------------------

EatNext is a community-driven restaurant discovery platform targeting the African market
(Yaound\'e, Douala, Limbe, and beyond). Users can search restaurants, read and write
reviews, file complaints, and save favorites. The technical specification is
\textbf{STA.pdf} (Crafti Digital Solutions).

The \texttt{develop} branch implements a full-stack monorepo:
\begin{itemize}
  \item \textbf{Backend} --- Node.js, Express, Prisma ORM, JWT auth, Swagger docs.
  \item \textbf{Frontend} --- React 19, Vite 6, TypeScript, Tailwind CSS, Leaflet maps.
  \item \textbf{Data} --- PostgreSQL~16 and Redis~7 via Docker Compose.
  \item \textbf{OSM integration} --- Overpass API called \emph{only} from the backend;
        PostgreSQL is populated exclusively through the EatNext REST API.
\end{itemize}

\subsection{Prisma Schema (\texttt{backend/prisma/schema.prisma})}

Seven models and five enums. Key enums:

\begin{itemize}
  \item \texttt{UserRole}: \texttt{user}, \texttt{owner}, \texttt{admin}
  \item \texttt{RestaurantStatus}: \texttt{pending}, \texttt{published}, \texttt{rejected}, \texttt{suspended}
  \item \texttt{RestaurantSource}: \texttt{USER\_SUBMITTED}, \texttt{OSM\_SYNC}
  \item \texttt{ComplaintType} / \texttt{ComplaintStatus} for moderation workflow
\end{itemize}

\textbf{User} --- \texttt{id}, \texttt{email} (unique), \texttt{passwordHash}, \texttt{fullName},
\texttt{role}, optional \texttt{googleId}, \texttt{isVerified}, \texttt{isBanned}.

\textbf{Restaurant} --- core fields plus OSM integration:

\begin{lstlisting}
model Restaurant {
  id           String           @id @default(uuid())
  name         String
  address      String
  city         String
  lat          Float
  lng          Float
  cuisineType  String
  priceRange   Int              // 1-4
  avgRating    Float            @default(0)
  reviewCount  Int              @default(0)
  status       RestaurantStatus @default(pending)
  source       RestaurantSource @default(USER_SUBMITTED)
  // OSM fields (added via migration 20250622120000_add_osm_fields)
  osmId        String?          @unique
  osmType      String?          // node | way | relation
  osmTags      Json?
  lastSyncedAt DateTime?
  openingHours String?
  phone        String?
  website      String?
  @@index([lat, lng])
  @@index([source])
}
\end{lstlisting}

\textbf{Review} --- one review per user per restaurant (\texttt{@@unique([userId, restaurantId])}).

\textbf{Complaint} --- typed complaints with status machine (\texttt{pending} $\rightarrow$
\texttt{under\_review} $\rightarrow$ \texttt{resolved} / \texttt{rejected}).

\textbf{Favorite} / \texttt{FavoriteList} --- user bookmarks, optionally grouped in lists.

\textbf{MenuItem} --- menu entries linked to a restaurant (\texttt{restaurantId}, \texttt{name},
\texttt{price}, optional \texttt{description}, \texttt{sortOrder}). Replaced atomically via
\texttt{PUT /restaurants/:id/menu}; cascade-deleted when the parent restaurant is removed.

\subsection{Migrations and Schema Push}

Migration \texttt{20250622120000\_add\_osm\_fields} adds the \texttt{RestaurantSource} enum,
OSM columns, unique index on \texttt{osm\_id}, and index on \texttt{source}.
Migration \texttt{20250622130000\_add\_menu\_items} adds the \texttt{menu\_items} table.

Local development typically uses:

\begin{verbatim}
cd backend
npx prisma generate

npm run db:seed             # tsx prisma/seed.ts
\end{verbatim}

Production-style deploy: \texttt{npx prisma migrate deploy}.

\subsection{JWT Authentication (\texttt{backend/src/middleware/auth.ts})}

\begin{lstlisting}
export function authenticate(req, res, next) {
  const header = req.headers.authorization;
  if (!header?.startsWith('Bearer '))
    return sendError(res, makeError('UNAUTHORIZED', '...', 401));
  req.user = verifyAccessToken(header.slice(7));
  next();
}

export function requireRole(...roles: UserRole[]) { /* 401 / 403 */ }
\end{lstlisting}

Protected routes use \texttt{authenticate}; admin-only routes add \texttt{requireRole('admin')}.
The JWT payload (\texttt{sub}, \texttt{role}) is attached to \texttt{req.user}.

\subsection{Services Layer (\texttt{backend/src/services/})}

Business logic is separated from route handlers:

\begin{itemize}
  \item \texttt{auth.service.ts} --- register, login, token refresh (bcrypt + JWT).
  \item \texttt{restaurant.service.ts} --- search, nearby, merged DB+OSM view, CRUD.
  \item \texttt{review.service.ts}, \texttt{complaint.service.ts}, \texttt{favorite.service.ts}.
  \item \texttt{admin.service.ts} --- moderation and analytics.
  \item \texttt{overpass.service.ts} --- Overpass API client (Section~\ref{sec:osm}).
  \item \texttt{osmSync.service.ts} --- OSM DTO $\rightarrow$ Prisma upsert (Section~\ref{sec:osm}).
\end{itemize}

Search results and nearby queries are cached in Redis
(\texttt{backend/src/lib/redis.ts}, TTL $\sim$10\,min for Overpass responses).

%----------------------------------------------------------------------
\section{OSM / Overpass Hybrid Architecture}
\label{sec:osm}
%----------------------------------------------------------------------

\textbf{Rule: the frontend never calls Overpass directly.}
All discovery and database population go through the EatNext API.

\begin{verbatim}
Frontend React  -->  API Express  -->  Overpass API
                           |
                           v
                    PostgreSQL (Docker) + Redis (cache)
\end{verbatim}

Full details: \texttt{docs/OSM.md}.

\subsection{Overpass Service (\texttt{backend/src/services/overpass.service.ts})}

\begin{itemize}
  \item Builds Overpass QL queries for food POIs: \texttt{amenity=restaurant|cafe|fast\_food|bar|...}
        and \texttt{shop=bakery} within a radius (100--50\,000\,m).
  \item Normalises raw elements into \texttt{OsmRestaurantDto} (name, lat/lng, address, city,
        cuisine, opening hours, phone, website, \texttt{osmTags}).
  \item Caches responses in Redis under keys like \texttt{overpass:nearby:...} (TTL 600\,s).
  \item Exports \texttt{searchNearby(lat, lng, radiusMeters, limit)} and
        \texttt{getByOsmId(osmType, osmId)}.
\end{itemize}

\subsection{OSM Sync Service (\texttt{backend/src/services/osmSync.service.ts})}

Maps Overpass DTOs to Prisma and upserts by unique \texttt{osmId}:

\begin{lstlisting}
export async function syncNearbyToDb(lat, lng, radiusMeters, limit) {
  const osmItems = await overpassService.searchNearby(...);
  const items = [];
  for (const dto of osmItems)
    items.push(await upsertOsmRestaurant(dto));
  await cacheDelPattern('restaurants:*');
  await cacheDelPattern('overpass:*');
  return { synced: items.length, items };
}
\end{lstlisting}

OSM restaurants are auto-published (\texttt{status: 'published'}, \texttt{source: 'OSM\_SYNC'}).
After sync they receive a UUID usable for reviews and favorites.

\subsection{Sync Endpoints (\texttt{backend/src/routes/restaurant.routes.ts})}

\begin{tabular}{@{}p{5.8cm}p{7.2cm}@{}}
\toprule
\textbf{Endpoint} & \textbf{Behaviour} \\
\midrule
\texttt{POST /v1/restaurants/osm/sync} &
  Body: \texttt{\{ lat, lng, radius?, limit? \}}.
  Batch upsert via \texttt{osmSyncService.syncNearbyToDb}. \\
\texttt{GET /v1/restaurants/osm/nearby?sync=true} &
  Fetch Overpass then persist before returning UUID-backed records. \\
\texttt{GET /v1/restaurants/osm/:type/:id?sync=true} &
  Single POI sync; returns persisted restaurant or 404. \\
\texttt{GET /v1/restaurants/nearby?includeOsm=true} &
  Merged view: PostgreSQL restaurants + live OSM POIs. \\
\bottomrule
\end{tabular}

Verify synced records:

\begin{verbatim}
SELECT count(*) FROM restaurants WHERE source = 'OSM_SYNC';
\end{verbatim}

\section{Frontend Code}
%----------------------------------------------------------------------

\subsection{Stack and Entry Point}

Vite~6 + React~19 + TypeScript. \texttt{frontend/src/main.tsx} wraps the app with
React Query (\texttt{@tanstack/react-query}) and toast notifications.
\texttt{frontend/src/App.tsx} defines routes inside \texttt{MainLayout}:

\begin{itemize}
  \item \texttt{/} --- \texttt{HomePage}
  \item \texttt{/search} --- \texttt{SearchPage} (filters + map + OSM sync)
  \item \texttt{/restaurants/:id} --- \texttt{RestaurantDetailPage}
  \item \texttt{/osm/:osmType/:osmId} --- \texttt{OsmRestaurantPage} (sync then redirect)
  \item \texttt{/login}, \texttt{/register}
  \item \texttt{/favorites}, \texttt{/profile} --- protected via \texttt{ProtectedRoute}
\end{itemize}

\subsection{API Client (\texttt{frontend/src/lib/api/client.ts})}

Axios instance with JWT injection from Zustand auth store.
All data comes from the backend API --- no local mock fallback:

\begin{lstlisting}
apiClient.interceptors.request.use((config) => {
  const token = useAuthStore.getState().tokens?.accessToken;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// Response interceptor: surfaces API error messages
\end{lstlisting}

Restaurant API calls live in \texttt{frontend/src/lib/api/restaurants.ts}:
\texttt{searchRestaurants}, \texttt{getNearbyRestaurants}, \texttt{syncOsmArea},
\texttt{syncOsmPlace}, \texttt{createReview}, etc.

\subsection{React Query Hooks (\texttt{frontend/src/hooks/useRestaurants.ts})}

Centralised query keys for cache invalidation:

\begin{lstlisting}
export function useSyncOsmArea() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (params) => restaurantApi.syncOsmArea(...),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: restaurantKeys.all }),
  });
}
\end{lstlisting}

Other hooks: \texttt{useRestaurantSearch}, \texttt{useRestaurant}, \texttt{useNearbyRestaurants}
(with \texttt{includeOsm} flag), \texttt{useCreateReview}.
Auth and favorites: \texttt{hooks/useAuth.ts}, \texttt{hooks/useFavorites.ts}.

\subsection{Key Pages and Components}

\textbf{SearchPage} (\texttt{frontend/src/pages/SearchPage.tsx}):
\begin{itemize}
  \item Two modes: database search (\texttt{GET /restaurants}) vs.\ proximity
        (\texttt{GET /restaurants/nearby?includeOsm=true}).
  \item Toggle ``Include OpenStreetMap''; ``Sync zone'' button calls
        \texttt{POST /restaurants/osm/sync} via \texttt{useSyncOsmArea}.
  \item List / map / split view; geolocation centres the map on the user.
\end{itemize}

\textbf{RestaurantMap} (\texttt{frontend/src/components/restaurant/RestaurantMap.tsx}):
Leaflet map with colour-coded markers --- blue for ephemeral OSM POIs,
green for PostgreSQL-backed restaurants. Links use \texttt{restaurantDetailPath}
or \texttt{/osm/:type/:id} for unsynced POIs.

\textbf{OsmRestaurantPage} (\texttt{frontend/src/pages/OsmRestaurantPage.tsx}):
On mount, calls \texttt{syncOsmPlace(osmType, osmId)} (\texttt{GET ...?sync=true}),
then redirects to \texttt{/restaurants/:uuid} so reviews and favorites work on a
persisted record.

\textbf{Layout}: \texttt{components/layout/MainLayout.tsx}, \texttt{Header.tsx},
\texttt{Footer.tsx}. UI primitives in \texttt{components/ui/}.
